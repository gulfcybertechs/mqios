The historical chat is not required to understand this list. Do not assume a future chat can recover it after deletion.

## Maintenance rules for future chats

Mohammed explicitly requested that this list remain maintained after deleting the chat.

1. Read this file and `CODEX_HANDOFF.md` before continuing the iOS work or planning Android parity.
2. For every requested feature, visual adjustment, behavior fix, reversion, or new test result, update the affected entries during the same task. Add new IDs for new capabilities and keep existing IDs stable.
3. Record the **latest decision** as the requirement. Keep superseded choices in the history/exclusions section so Android does not accidentally reproduce a rejected design.
4. Keep iOS implementation status, user/device validation, and Android status distinct. Source presence or a static script passing is not a successful build or device test.
5. For Android, use the same IDs and record its source locations, implementation status, and actual validation when the repository is available. Do not assume SwiftUI types, SF Symbols, point values, UserDefaults keys, or Apple Liquid Glass APIs translate directly.
6. Record any platform-specific adaptation and obtain clarification only when it materially changes the requested product behavior. Preserve icon-only navigation, direction, state, control grouping, and interaction outcomes.
7. Update `CODEX_HANDOFF.md` with a short summary, open issues, current source checkpoints/backups, and a pointer to this registry. Synchronize local document copies when accessible; project-root copies are authoritative.
8. Keep future changes small and backed up. Never use the parity effort as permission to redesign page layout or disturb unrelated learning, translation, memorization, login, or audio behavior.
